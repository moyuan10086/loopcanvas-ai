# Infinite Canvas 多模型创作工作台——项目记录

## 一句话定位

在开源 Infinite Canvas 的无限画布基础上，面向真实 AI 视觉生产场景完成二次开发：把多渠道模型、价格决策、批量循环、电商卖点图、异步任务恢复和本地后端持久化整合成一套可持续使用的创作工作台。

## 项目背景与我的工作边界

- 开源基座：`basketikun/infinite-canvas`
- 基线版本：上游 `v0.8.2`（`0c4288b`）
- 个人归档版本：`v0.8.2-moyuan.1`
- 技术栈：React、TypeScript、Vite、Zustand、Ant Design、Node.js Canvas Agent、IndexedDB
- 开源合规：保留原作者、来源、前端标识与 AGPL-3.0；明确说明为二次开发，不将原项目能力包装成个人原创。

我的主要工作集中在需求拆解、交互设计、前后端实现、供应商协议适配、可靠性治理、数据持久化、成本管理和持续调试。上游原有的无限画布、基础节点系统与通用 AI 创作框架属于开源基座。

## 为什么要改

上游适合作为通用创作画布，但真实使用中出现了四类核心问题：

1. 不同供应商协议、异步任务和返回结构差异大，通用 OpenAI 兼容调用不足以稳定落地。
2. 图片和视频模型数量多、计价单位和充值汇率不统一，选择模型时缺少直接成本依据。
3. 电商卖点图、换装、九宫格扩图和超分属于重复工作，需要可解释、可停止、可恢复的批处理流程。
4. 画布、媒体和配置主要依赖浏览器存储，刷新、清缓存、换浏览器或多标签页时存在数据丢失风险。

## 核心方案

### 多渠道协议层

建立统一渠道与模型配置，在统一生成入口下按供应商分派协议。针对 APIMart、ToAPIs、DeepKey、RunningHub、ModelScope 等实现异步提交、轮询、错误透传、代理和结果归一化；同时保留自定义调用脚本能力。

### 循环执行引擎

把循环节点定义为“调度器”而不是普通生成节点：它负责输入素材、固定参考图、逐轮提示词、执行方式和下游步骤编排。串行模式保证慢速渠道稳定；并行模式采用固定 4 worker，避免几十个请求同时冲击供应商。

卖点图模式在此基础上增加约束：第 N 轮只发送第 N 条卖点，所有商品参考图每轮固定复用，运行前校验图片和卖点数量，结果按轮次分支布局。

### 可靠引用模型

将“连接”和“参考”拆开：源图、显式 `@`、隐式连接、固定参考图分别表达不同意图。生成记录保存固定图片索引、引用节点 ID、可读标签和媒体存储键，重试时恢复原始 `generationType` 与参考图，避免编辑请求退化为纯文生图。

### 双层持久化

浏览器 IndexedDB 提供离线体验，本地 Canvas Agent 提供项目、媒体、配置和 API 日志的持久化。同步逻辑使用修订号、最新快照优先和旧响应隔离，防止初始化空状态、多标签页或延迟响应覆盖新数据。

### 成本与可观测性

模型价格统一换算成人民币，并保留渠道充值/汇率规则；API 统计记录渠道、模型、类型、状态和耗时，帮助定位慢请求、失败渠道和实际使用成本。

## 难点与工程取舍

- 非幂等 AI 请求不能简单自动重试：网络断开不代表供应商没有执行，自动重提可能重复扣费。因此对“已提交但结果未知”和“明确未提交”采用不同错误策略。
- 参考图不能只靠连线推断：同一张图可能是主体、轮换素材或固定风格参考，因此在数据结构中显式保存引用角色和来源。
- 后端同步不能把浏览器空状态当真：首次连接、换浏览器和多标签页会产生竞态，因此采用合并、修订号和旧响应隔离。
- 并发越高并不等于越快：图片渠道通常有队列和连接上限，卖点图默认串行，普通并行也必须有界。

## 简历表述

### 精简版

基于 AGPL-3.0 开源 Infinite Canvas 二次开发多模型 AI 视觉工作台，使用 React、TypeScript、Vite 与 Node.js 完成多供应商协议适配、循环批处理、电商卖点图、模型成本管理和本地后端持久化。

### 项目要点版

- 设计并实现可视化循环执行引擎，支持编号提示词、固定/轮换参考图、多步骤级联、串行及 4 worker 有界并发，落地商品卖点图等批量生产流程。
- 统一适配 DeepKey、ToAPIs、APIMart、RunningHub、ModelScope、ComfyUI、MiniMax 等渠道的同步/异步协议、代理、轮询、错误解析与结果恢复。
- 构建浏览器缓存 + 本地 Agent 的双层持久化方案，引入修订冲突保护和旧响应隔离，提升画布、媒体、配置及 API 统计的跨刷新恢复能力。
- 建立模型人民币价格与 API 可观测体系，处理不同渠道的充值换算规则，并通过路由懒加载和 Rollup 分块降低首屏 JavaScript 负担。
