# 待测试

- 批量图片单项操作：展开图片组并悬停子图片时，应能看到下载、创建副本和删除；失败子图片额外显示重试。删除后根节点的数量、主图和画布连线应同步更新；创建副本后应得到普通独立图片节点，不再跟随原图片组折叠、批量删除或批量重试。
- Freestylefly 提示词来源：打开提示词库并刷新后，应出现 `freestylefly-gpt-image-2` 分类及公开模板；模板正文可搜索、复制并插入画布，来源拉取失败时不应清空其他来源的缓存内容。
- 本地 Codex Agent 任务控制：连接新版 Agent 后，输入框下方应显示权限、模型和推理强度选择；刷新后保留用户选择，模型切换时推理强度应自动适配模型支持范围。“请求批准”下执行命令、修改文件或申请额外权限时应出现授权卡，可选择拒绝、仅本次允许或本会话允许；“自动审查”仅对高风险操作请求批准；“完全访问”应明确显示高风险提示且不再询问。点击停止应只终止当前轮次，随后仍可在同一会话继续发送消息；停止发生在授权等待阶段时不得遗留旧授权卡。旧版 Agent 缺少模型接口时，对话仍应可使用默认模型，不得阻止发送。
- 前端路由懒加载与分包：分别直接打开 `/`、`/image`、`/video`、`/assets`、`/prompts`、`/canvas`、`/canvas/:id`、`/config` 和不存在的路径，页面加载占位不得造成白屏或布局跳动，刷新后路由应正常恢复；首页未打开配置弹窗时不得预加载 CodeMirror 编辑器块，首次打开配置弹窗应正常显示全部标签和脚本编辑器。生产构建应生成独立页面块及 React、Ant Design、编辑器、动画和 Markdown vendor 块，路由切换时不得重复加载或出现循环依赖错误。
- 循环节点视觉与尺寸：新建循环节点应使用 460×520 默认尺寸，缩放时不得小于 420×420；浅色与深色主题下都应清晰区分“生成规则 / 循环内容 / 商品参考素材 / 底部执行栏”。卖点图模式只在商品参考素材卡中显示左侧连接图和固定参考图，不再额外出现重复的图片输入卡；大量参考图应横向滚动，底部生成按钮在正文滚动时保持可见，现有卖点拆分、参考图复用和运行逻辑保持不变。
- 画布反向与循环连线：无论节点相对位置如何，连线都应严格从源节点右侧输出口连接到目标节点左侧输入口，并使用无折角的单段连续曲线。循环结果只显示“循环 → 本轮首步骤 → 后续步骤”的执行关系；循环输入图或固定参考图即使记录在 `referenceNodeIds` 中，也不得额外直连某一轮结果。载入旧画布或再次运行循环后应自动移除这种重复边，手动尝试重复连接时应给出提示。
- 卖点图运行稳定性：首次启用卖点图或载入旧版自动并行的卖点循环时，运行方式应默认为“按顺序”；三个 DeepKey 图片编辑请求不得再自动同时发出。用户手动选择“同时运行”后才允许并发，切回按顺序后应等待前一轮完成再提交下一轮。
- DeepKey 长耗时图片编辑：图片生成不得要求连接 Canvas Agent。未连接、Agent 离线或旧版不支持代理时，应在无扣费能力探测后自动浏览器直连；新版 Agent 可用时，`gpt-image-2-count` 的 multipart 图片编辑通过后端保存的对应渠道转发，网页请求中不得携带供应商 API Key。Agent 无法连接上游时节点应显示具体网络码或超时说明；已向代理提交后的结果不确定时不得自动改走直连，避免重复扣费。
- 卖点图失败节点重试：保存为 `generationType: edit` 且带 `references` 的循环结果，即使原提示词没有显式 `@`，点击重试仍须恢复全部商品参考并调用 `/images/edits`；不得改成无参考图的 `/images/generations`。DeepKey 非流式任务经本地代理应允许等待最多 300 秒，后台 176–199 秒成功记录不得因前端 120 秒连接中断而提前显示失败。
- 循环卖点图模式：切换到“卖点图”后，应优先使用循环节点内直接填写的至少 2 条 `1.` / `2.` 编号卖点，并可从右侧空白生成模板或上游文本导入；带“循环 N”标记的历史生成结果不得误作模板。填写后自动同步生成张数。连接一张或多张商品图后，每轮必须复用全部商品参考，第 N 轮只发送第 N 条卖点及商品一致性约束，不能继续把整份清单交给模型自行选择；卖点不足或没有商品图时按钮禁用且运行端也应拒绝，“直接生图”流程也应可运行。切回通用循环后原有逐轮指令、素材轮换与变量保持不变。
- 外部渠道入口导入：从 chatgpt2api 等页面携带 `baseUrl` 与 `apiKey` 进入无限画布时，应按标准化 Base URL 更新对应渠道；未匹配时新增独立渠道且保留原第一项，重复进入不得创建重复渠道，缺少或非法 Base URL 时不得改动配置。
- Windows 一键启动 MCP 注册：Codex CLI 未注册 `infinite-canvas` 时运行 `start-infinite-canvas.cmd`，脚本应在 Web 与 Agent 健康检查后自动执行注册并继续显示 READY，不得因 `No MCP server named 'infinite-canvas' found` 直接退出；已注册时再次启动应只显示“already registered”，不能重复添加。
- 循环固定参考图选项：循环节点“附加输入”区域应支持一次上传多张图片，以及从当前画布图片中搜索多选；下拉选项点击后不得因画布抢占鼠标事件而失效。上传后逐张显示缩略图、名称和移除操作。未选择时不应隐式猜测固定图。选中多张固定图后，每轮请求均包含全部固定图，同时分别包含当轮衣服 1、2、3；固定图组不占用“每轮 1 张”的轮换名额。每轮提示词旁应出现 `@固定图` 按钮并在当前光标位置插入，`@固定图` 指代整组固定图；它与 `{{i}}`、`{{r}}`、`{{n}}` 在输入框正文中应以低饱和蓝色文字、浅色底和细下划线区别于正文，且不影响光标、选择、滚动或粘贴。使用固定图引用后，全部固定图与当轮衣服仍应同时传入。删除任一已选图片后运行应明确提示重新选择，不得静默忽略。
- 图片编辑主参考：在已有模特图片节点中显式 `@` 一张衣服图后直接生成，结果的 `references`、`referenceNodeIds` 和 `referenceLabels` 应先包含模特源图，再包含衣服图；开启“隐式参考”时同样保留源图并追加连接素材，关闭且未 `@` 时只使用源图。循环运行步骤模板时不得误把模板结果自身追加为第三张参考。
- 新 Profile 画布同步：Canvas Agent 的配置已授权 `http://localhost:3000` 后，在新的浏览器 Profile 打开 `/canvas`，无需手工填写 Token；全站 Agent 应静默自动连接，随后侧边栏以后端 `~/.infinite-canvas/canvas-projects.json` 为主源，不再保留该 Profile 陈旧的 IndexedDB 项目。只有存在明确的离线脏标记时，本地新修改才能按时间参与合并，后端确认项目和媒体保存后应清除脏标记。未列入 Agent `origins` 的网页来源访问 `/config` 时只能看到 `hasToken`，不得得到 Token；响应不得被缓存。
- 控件与主页质感：Input、InputNumber、Select 及画布自定义输入控件应保持原主题配色和 1px 边框；悬停只增强边框，键盘或点击聚焦时显示柔和的 3px 外圈且不得引起尺寸跳动。主页必须保留原黑白暖灰主题，移除虚线圆装饰，主标题尺寸更克制，常见桌面和移动视口首屏应露出后续内容；主按钮、次按钮和提示词作品卡使用微弱双层阴影，作品卡具备清晰的 hover 与 focus-visible 状态且不得出现强光晕。
- 循环节点防堆积：循环内容超出节点高度时，只允许中间内容区滚动；底部“生成张数 / 重复几次”和执行按钮应始终占据独立区域，不覆盖最后一条提示词、变量按钮或错误信息。滚动到底部后应保留正常间距，开关标题应完整显示；缩放节点后布局仍不得重叠。
- Coze / Arco 布局规范：必须保留项目原有的暖灰画布、黑色主按钮、既有选中蓝及深色主题配色，不得替换主题色。图片、视频、文本、音频、配置和循环节点应使用 16px 圆角和轻量半透明表面，内部控件以 8px 圆角为主，并保持清晰的主次文字层级。节点标题左侧保留克制的类型色点；悬停时只增强阴影，选中时显示原有蓝色描边及四角缩放点，左右连接锚点仅在悬停、选中或连线时出现。图片和视频内容不得溢出圆角。
- 循环纯文字生图：循环节点不连接右侧处理步骤时，应显示“直接生图”和当前默认图片模型说明；“沿用每步指令”仍显示但不可操作，“重复几次”改为更明确的“生成张数”。填写一条每轮指令、生成 3 张并选择“同时运行”后，按钮应显示“生成 3 张”，直接并发创建 3 个分别连接到循环节点的图片结果，每轮固定请求 1 张且不需要参考图。连接上游文本时也应能逐轮取用；没有任何文字指令时按钮应禁用。连接右侧图片、视频、音频或文本生成节点后应恢复原多步骤循环模式，并重新启用“沿用每步指令”。
- 画布 Agent 持久化：连接本地 Agent 后，现有浏览器画布应按项目 ID 和更新时间首次合并到 `~/.infinite-canvas/canvas-projects.json`，画布变更应绕过浏览器缓存回调直接进入后端串行保存队列；必须先保存节点、连线和 `storageKey` 项目 JSON，再同步大图片或视频，单个媒体上传失败不得阻止节点落盘。生成期间连续产生占位和成功快照时，旧快照完成后不得回写前端或先阻塞同步全部媒体，最新成功 JSON 应优先落盘；修订冲突遇到同一节点的生成中占位与已完成媒体时必须保留 `storageKey`。后端确认最新快照成功前不得清除脏标记，有连接的网络失败应自动重试，Agent 每次重连都应强制拉取、合并并回写。节点图片、视频和音频落入浏览器缓存后应立即尝试写入 `canvas-files/`；后端项目 JSON 不得保留 `blob:` 临时地址。换浏览器或切换 `localhost` Profile 后，即使节点 `content` 为空，也应按 `storageKey` 自动下载缺失媒体并正常显示。多个标签页同时修改时，修订号冲突不得静默覆盖已有项目；Agent 离线后恢复连接的首次保存也不得用空项目列表覆盖后端。IndexedDB 只能作为离线缓存，不能决定后端保存是否触发。
- 图片引用索引：图片节点右上角继续显示当前画布顺序生成的“图片1 / 图片2”，样式和用途保持不变；每张图片左下方另显示跨画布固定的 `IMG-XXXXXXXXXXXX` 索引，删除或重排节点后不得变化。新生成图片的节点信息应同时记录引用文件键、引用节点 ID 和 `IMG-索引 · 图片 N · 节点标题`；已有引用标签打开画布后自动补充固定索引，重试仍按文件键和节点 ID 指向同一张图片。
- API 统计 Agent 持久化：首次打开 API 统计时应合并浏览器旧日志与 `~/.infinite-canvas/api-usage.json`，新请求完成后两边各新增一条且最多保留 2000 条；换浏览器应看到同一批日志，确认清空后浏览器与 Agent 都为空，统计内容仍不得包含提示词正文、上传内容或 API Key。
- 提示词封面解析与回退：YouMind 提示词的 `Language / Featured / Raycast` 徽章不得被当成卡片封面，应显示“生成图片”区域的真实作品；`RAW iPhone 质感：地铁站`、`米粒微型文字`、`360 等距柱状全景图` 等 `pbs.twimg.com` 封面应优先通过图片代理加载。原图不可用时应显示固定图片占位，不得出现破图图标、alt 标题或卡片高度跳动，详情弹窗行为应一致。
- 循环失败反馈：循环任一轮执行失败时应立即弹出首个具体错误，并在节点底部执行参数之前显示完整失败轮次；选中失败的循环节点后点击顶部“重试”应重新执行循环，而不是进入普通图片重试或提示找不到提示词。上一次循环仍在停止收尾时重复运行，应明确提示稍候。
- 画布 API 统计：点击画布底部工具栏的统计图标，应显示今日调用次数、成功率、平均耗时、失败数及最近 5 次请求；新的生成请求完成或失败后面板应实时更新，点击“全部记录”应进入完整 API 统计页，点击画布空白处应关闭面板。
- APIMart GPT Image 2：使用 `apimart::gpt-image-2` 生成 `16:9` 图片时，请求应向 `/v1/images/generations` 发送比例字符串与可选 `resolution`，取得 `task_id` 后轮询 `/v1/tasks/{id}` 并从 `data.result.images[].url[]` 保存图片；不得再发送 `1824x1024`、`response_format` 或按同步图片响应误报“请求失败”。图生图应通过同一接口的 `image_urls` 提交。
- 图片节点参考图去重：一个已有内容的图片节点仅连入一张图片后再次生成，节点元数据 `references` 应只包含直接连入图片一项，不得再叠加当前节点自身；没有连入媒体时，直接编辑仍应使用当前图片自身作为唯一参考。
- 循环结果自动布局：运行至少 3 轮、3 个步骤的图片或视频流程，生成结果应按步骤横向成列、按轮次纵向成行；不同尺寸节点不得相互重叠，每行连线应保持独立且不穿过其他轮次节点。
- 循环分支与参考图：循环 3 轮时应从循环节点直接发出 3 条独立分支连线，每个分支的后续节点只连接本轮上一步结果，右侧步骤模板不得再向生成结果扇出连线。未开启“附加输入”时首步请求应为 0 张参考图；开启并连接 1 张左侧图片时首步应为 1 张，后续步骤也只应收到本轮上一张结果，不得累加模板图片。
- 循环逐轮指令：左侧只连接一张图片，在“每轮指令”中分别输入三条内容，或粘贴 `1. ... / 2. ... / 3. ...` 编号列表，应自动拆成三条并把轮数同步为 3；三轮都应复用同一张输入图，但分别使用第 1、2、3 条指令。连接多张图片时仍应按素材顺序逐轮取用。
- 循环失败续跑：执行三轮以上的多步骤流程时，单轮网络或供应商错误不得自动重提非幂等生成请求；某轮失败只停止该轮剩余步骤，后续轮次继续执行。结束后循环节点应显示“完成 x/n 轮”及失败轮次，不得在第一次失败处吞掉后续任务。
- 循环节点有界并发：选择“同时运行”并把执行轮数设为 9 后，应保持最多 4 个任务同时运行，最终完成 9 轮；切换“按顺序”后仍应逐个执行。
- 循环变量光标插入：把光标放到提示词中间再点击 `{{i}}`、`{{r}}` 或 `{{n}}`，变量应插入到光标处而非句尾；选中文字后点击变量应替换选区，插入后文本框继续保持焦点且光标位于变量后。
- 循环节点界面与耗时：循环节点应紧凑显示模式、输入开关、取图信息、提示词变量和执行参数，变量按钮直接显示 `{{i}} / {{r}} / {{n}}`；失败信息在卡片内单独成区。循环是调度器，不应显示绿色生成耗时标签，实际生成出的图片、视频、音频或文本节点仍应显示各自耗时。
- 循环重跑处理链：把多个已有图片/视频/音频/文本生成节点按顺序连接到循环节点后，面板应显示步骤链；默认“步骤提示词”开启时，每轮沿用每个下游节点原提示词，并把本轮上一步的新结果传给下一步。关闭“追加指令”时不应自动加入占位提示词；关闭“步骤提示词”后才使用循环自己的追加指令完成批处理。
- 模型自定义价格：“模型价格管理”默认应折叠，不得挤压启用模型和默认模型区域；展开后选择渠道，再通过可搜索下拉一次选择一个已有模型，必须显示完整模型名、能力和当前价格，不得铺出几十个无名称的空白价格输入框。已选模型的完整模型 ID 应显示在只读文本框中，聚焦可全选，右侧复制按钮应把未截断 ID 写入剪贴板。价格输入框应直接显示当前内置或抓取价格，首次聚焦基础价格时应全选，便于直接覆盖；填写 `¥0.08/张`、`¥1.20/秒` 或 Token 价格后，启用模型多选、默认模型选择器、画布及工作台模型下拉应立即显示自定义价格并标记“自定义”；刷新页面和重启本地 Agent 后价格应保留；清空输入应恢复并重新显示内置价格。
